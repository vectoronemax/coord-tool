# Vector的坐标转换器

WGS-84 ⇄ GCJ-02 ⇄ BD-09 六向互转：单点即时换算，或整表批量转换，自动揪出写反、越界、国外、海上的坏点。全部本地计算，不调用任何在线 API。

## 快速开始

```bash
cd apps/coord-tool
pip install -r requirements.txt
streamlit run app.py
```

浏览器会打开 http://localhost:8501 。**一定要在 `apps/coord-tool` 目录里启动**：Streamlit 只读启动目录下的 `.streamlit/config.toml`，在别处启动页面能用，但主题色和「不发送使用统计」的设置不生效。

## 三个坐标系

| 坐标系 | 谁在用 | 说明 |
|---|---|---|
| WGS-84 | GPS 原始坐标、Google Earth、OpenStreetMap | 国际通用 |
| GCJ-02 | 高德、腾讯、苹果中国区地图 | 国测局加密坐标（"火星坐标"），在 WGS-84 上做非线性加偏，国内一般偏几百米 |
| BD-09 | 百度地图 | 在 GCJ-02 上再加一层百度自己的偏移 |

## 用法

**单点转换**：填经度、纬度，选源坐标系和目标坐标系，立即给出结果和偏移距离（米）。零值、写反、国外、海上的点不转换，直接告诉你原因。

**批量转换**：

1. 上传 CSV（UTF-8 或 GBK 都行，所有列按文本读，前导 0 等原样保留）
2. 选经度列、纬度列、源坐标系（按列名自动猜，请核对）
3. 点「转换」
4. 表格预览：问题行标红，可切到「只看问题行」
5. 地图预览：高德底图（GCJ-02）/ OSM 底图（WGS-84）切换；蓝点 = WGS-84，橙点 = GCJ-02，中间连线，悬停看点名和偏移米数；红叉 = 问题点
6. 下载结果 CSV（utf-8-sig，Excel 直接打开不乱码）

### 输出列

原始列全部保留，后面追加：

| 列 | 含义 |
|---|---|
| `wgs84_lng` `wgs84_lat` / `gcj02_lng` `gcj02_lat` / `bd09_lng` `bd09_lat` | 三套坐标 |
| `gcj02_offset_m` `bd09_offset_m` | GCJ-02、BD-09 相对 WGS-84 的偏移（米） |
| `province` | 落在哪个省级区（按 GCJ-02 判断） |
| `check` | 正常 / 问题 |
| `issue` | 问题类型，见下表 |
| `check_note` | 具体说明，例如「交换后落在北京市，请核对后交换」 |

### 校验规则

**只有「正常」的点才转换**。问题行**不删、不自动改、不转换**（坐标和偏移列留空），`check_note` 写原因。单点转换用同一套规则。

每行只标一个最能说明问题的类型，按下面的顺序判断：

| 顺序 | 类型 | 判断 |
|---|---|---|
| 1 | 缺失或非数字 | 经度或纬度为空、不是数字 |
| 2 | 超出范围或零值 | 恰好是 (0, 0)：多半是缺失值被填成 0。直接套 BD-09 公式会得到 (0.0065, 0.006)，看着像真坐标 |
| 3 | 正常 | 落在某个省级行政区内 |
| 4 | 经纬度写反 | 交换经纬度后落进省级区（数值没越界也能认出，比如乌鲁木齐） |
| 5 | 超出范围或零值 | 经度超出 ±180 或纬度超出 ±90 |
| 6 | 落在国外 | 在中国范围框外（GCJ-02 / BD-09 只在国内地图上用） |
| 7 | 框内但不在省级区 | 在中国范围框内，但不在任何省级区（海上或邻国），说明里给最近省份和距离 |

### 怎么发现「源坐标系选错了」

光看数字分不出 WGS-84 和 GCJ-02，要靠地图：

- 源数据真是 WGS-84：高德底图上**橙点**压在正确位置，OSM 底图上**蓝点**压在正确位置。
- 若高德底图上反而是**蓝点**压在路口、橙点偏出几百米：源数据其实已经是 GCJ-02（多半是从国内地图上取的点），把源坐标系改成 GCJ-02 重新转换。

实例：课程数据 `data/raw/坐标点位_待转换.csv` 的 `lon_wgs84 / lat_wgs84` 两列，实测是 GCJ-02。

## 算法说明

- **WGS-84 → GCJ-02**：开源社区流传的公开加偏公式（克拉索夫斯基椭球参数 + 正弦扰动项）。非官方发布，主流开源库都用这一版；中国范围框外不加偏。
- **GCJ-02 → BD-09**：百度公开的 x_pi 公式。
- **反算**（GCJ-02 → WGS-84、BD-09 → GCJ-02）：公式没有解析逆，用迭代法：从目标点出发，每轮正算一次、把残差（正算结果 − 目标）扣回去，固定修正 5 轮。外滩 WGS → GCJ → WGS 往返误差逐轮如下：

  | 修正轮数 | 0 | 1 | 2 | 3 | 4 | 5 |
  |---|---|---|---|---|---|---|
  | 往返误差 | 479 m | 2.2 m | 7 mm | 0.025 mm | 0.0001 mm | 0（浮点精度内） |

  网上常见的「一步反算」就是只修正 1 轮，差 2 米多。BD-09 的一步反算公式在天安门约差 5 厘米，也改用同样的 5 轮修正。
- **WGS-84 ⇄ BD-09**：经 GCJ-02 中转。
- **偏移距离**：转换前后两组数字画在同一张图上的球面距离（半正矢公式，地球平均半径 6371008.8 米）。

## 离线计算、不上传数据

- 所有换算和校验都在本机运行的 Streamlit 程序里完成，上传的 CSV 只读进本机内存，不发往任何服务器。
- `.streamlit/config.toml` 关掉了 Streamlit 的使用统计（`gatherUsageStats = false`）。
- 唯一联网的是**地图预览**：底图瓦片来自高德、OSM 服务器，地图脚本（Leaflet）来自 CDN。瓦片请求会暴露你在看哪块地图，但不含你的数据。关掉页面上的「显示地图」即完全离线。

## 数据来源与限制

- 省级边界：阿里云 DataV.GeoAtlas（GCJ-02，34 个省级区，含台湾、香港、澳门和南海诸岛；去掉了九段线要素），从课程第 2 天数据包复制。边界经过简化，紧贴海岸线的点可能被标成「框内但不在省级区」而不转换，说明里有最近省份和距离，核对后可手动处理。
- GCJ-02 公式不是官方发布的版本。实测 10 个城市地标在高德、OSM 底图上目视对得上，但不保证与官方算法逐位相同。
- 中国范围框是粗略矩形，首尔、河内这类邻国城市也在框内，会被标为「框内但不在省级区」。
